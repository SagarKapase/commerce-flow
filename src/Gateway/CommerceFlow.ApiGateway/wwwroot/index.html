Catalog anonymous

        

          GET /api/products needs no token — reads are public.
          Writing one needs the Admin role, which is why the gateway
          passes this route through without an authorization check: the same path
          is public for GET and restricted for POST, and only Catalog knows that.
        


        

          
          
          
          
          
          
        

        

          
          
        


        

        

      


      
      

        
Basket token required

        

          The basket owner comes from the token's sub claim. There is no
          user id in any URL here — sign in as somebody else and this list changes
          entirely, using the exact same endpoint.
        

        

          
          
        

        


        

          
Checkout

          

            POST /api/orders sends only the shipping address.
            The items and prices come from the basket, server-side — there is no field
            in this request that could name a product or a price.
          

          

            
            
            
            
          

          
        

      


      
      

        
Orders token required

        

          There is no PUT /api/orders/{id} anywhere in this system. An order is a
          record of a commitment, not an editable document, so the only things you can do to
          one are business operations: /pay and /cancel.

Endpoint map

        

          Every endpoint this UI can reach, and the service behind it. The browser only
          ever addresses https://localhost:7100.
        

        


        
Deliberately unreachable

        

          These exist on their services but have no route in the gateway,
          so the browser gets a 404 without the service ever being contacted. That is how
          internal APIs are kept internal — not with a permission check somebody can
          forget, but by removing the address.
